## Engine behavior and bounds

- No new engine operation needed. `instruction` entries intentionally use the existing compiler's no-op path to show preparation, writing and adhesive instructions.
- Accordion hinge i: x=-56.25 for odd i, x=-75 for even i. Fold side -1 odd/+1 even. Each fold selects previous nested tag and adds `pleat-i`. Reopen i=7→1 with angle=-side*150 degrees. Already opened descendants follow upstream folds rigidly; no changing silhouette.
- Name tent uses `fold` with `angle:120`; second fold selects `not:'top-wall'`, so no flat splitting is attempted on the first standing wall. Its ridge coordinates meet at y=0, z=(148/3)*sqrt(3)/2.
- Bookmark is the only project using `tuck`. Both cap and tucked tips have the same horizontal physical hinge y=-R/2. The engine's generic lift/reorder/close operation conveys insertion; it is not a collision or finite-thickness simulation.
- Original compile succeeded for each. Surface area was checked at t=0,.25,.5,.75,1 in every transition. Largest absolute area error below 2e-11 mm². Triangle has 11250 mm²; 150 mm squares 22500 mm²; name tent 31080 mm². Final posters for accordion, wrapper, name tent and taped wallet were rendered with Blender preview (8 samples, 2 threads) and visually checked. Root visually checked the first four. The name tent is a correct closed triangular prism, though the near-overhead camera makes its side profile subtle.
